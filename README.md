# Secure Employee QR Register

A cybersecurity-focused Python/Tkinter desktop application for registering employees while reducing credential, spreadsheet, QR, and privacy risks.

## Security features

- No password or username is stored in source code.
- Credentials load from environment variables or ignored `LOCAL_CREDENTIALS.txt`.
- Constant-time credential comparison and a 30-second lockout after five failed attempts.
- Password input is masked and weak/missing configuration fails closed.
- QR codes contain a random employee ID and an HMAC-SHA256 signature, not employee PII.
- CSV cells are neutralized against spreadsheet-formula injection.
- Employee input is validated before storage.
- Record and QR filenames are generated by the application, preventing path traversal.
- Runtime records, QR images, and credentials stay local and are excluded from Git.

## Local setup

Requires Python 3.10 or newer. Tkinter is included with the standard Windows Python installer.

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

The owner-specific `LOCAL_CREDENTIALS.txt` is intentionally absent from GitHub. For a new installation, copy `LOCAL_CREDENTIALS.example.txt` to `LOCAL_CREDENTIALS.txt`, replace every placeholder with unique values, then run:

```powershell
python main1.py
```

Environment variables can be used instead and take precedence:

```text
EMPLOYEE_APP_USERNAME
EMPLOYEE_APP_PASSWORD
QR_SIGNING_KEY
```

## Privacy model

Employee records are stored under the ignored local `data/` directory. Generated QR images are stored under ignored `qr_codes/`. A QR token can identify a local record and detect tampering, but it does not reveal the employee's name, birth date, address, gender, or country.

## Important scope

This application protects a single-user local workflow. For multi-user or enterprise deployment, use centralized identity, an encrypted database, key rotation, operating-system access controls, backups, and managed audit logging.
